# C++ 版交互动效设计（操作清单 → 动效映射）

日期：2026-11-11
范围：`cpp/shell/ui` 全部可交互入口 + `cpp/shell/reader.cpp` 的视口过渡
原则：**按 C++ 版自己的页面栈 / 浮层 / 自绘控件模型独立设计**，不照搬 Python 的
动画覆盖范围（Python 只有换页覆盖层 + 抽屉 + 开关三处；这里补齐到所有操作）。

---

## 1. 为什么不能"每个操作配一个动画"

C++ 版是 Widgets + 少量 QML 的混合树，动画能动的属性只有三类：

| 可动 | 不可动 |
|---|---|
| `QGraphicsOpacityEffect::opacity` | 布局几何（每帧 relayout 会重排滚动容器与 QQuickWidget） |
| 浮层控件 `pos`（不在布局里的子控件） | `QWidget` 尺寸（除侧栏收起，见 §3.6） |
| 自绘参数（`paintEvent` 里的偏移/相位/透明度） | 子控件 `QSS` 状态（无中间态） |

因此动效只做三件事：**淡入淡出、整体位移、自绘参数补间**。任何"缩放/旋转控件"的
需求一律不做（Widgets 无 transform），改用位移或透明度表达。

## 2. 统一表（时长 / 曲线）

| 档位 | 值 | 用途 |
|---|---|---|
| `Instant` | 0 | 动效关闭时的退化路径 |
| `Fast` | 120ms | 微反馈：涟漪消失、文字块替换、翻页淡出 |
| `Base` | 180ms | 内容替换：交叉淡出、浮层进出、工具条、对话框 |
| `Slow` | 240ms | 大幅位移：抽屉 |
| `Page` | 250ms | 换页（与 `PageTransition` 默认时长一致） |

三条曲线，语义固定（`motion.cpp`）：

* `EnterCurve()` = OutCubic —— 进场/落位：起步快、尾巴收敛
* `ExitCurve()` = InCubic —— 退场/离场：先慢后快，收得干净
* `MoveCurve()` = InOutCubic —— 两端缓的位移（下划线滑动等）

同一语义在全站只允许一条曲线，避免"同一个动作在不同页面观感不同"。

## 3. 操作清单与动效映射

### 3.1 页面栈（`ui_main_window.cpp` + `page_transition.*` + `qml/PageSwipe.qml`）

| 操作 | 入口 | 动效 | 参数 |
|---|---|---|---|
| 进入下一层（卡片→详情、详情→阅读、空态→登录） | `Go(id, true)` | 旧页左移、新页右侧推入 | `Page` / OutCubic |
| 返回上一层（返回键 / Esc / 系统返回 / 边缘右滑 / 面包屑上跳） | `Back()`、`GoToCrumb()` | 反向推回 | `Page` / OutCubic |
| 左侧导航同级切换（导航栏、底部分组、抽屉内导航） | `Go(id, false)` | 交叉淡入（无位移） | `Base` / InOutQuad |

**为什么同级切换不用位移**：位移在用户心智里等于"进入了新层级"。从"首页"点"设置"
不是深入，而是平级跳转，用位移会让人以为随时可以"返回上一级"（实际返回栈根本没变）。
这条规则由 `NavMotion` 三值枚举表达：`Push / Pop / Lateral`。

QML 侧新增 `mode` 属性（0=push 1=pop 2=fade）：淡入模式两页 `x` 恒为 0，只补
`opacity`；位移模式两页共用同一个设备像素取整后的 `offset`（保留原有防 1px 竖缝约束）。

### 3.2 外壳浮层

| 操作 | 实现 | 动效 |
|---|---|---|
| 面包屑内容变化 | `RebuildCrumbs` | 旧行 120ms 淡出（`CrossFade`） |
| 侧栏收起/展开 | `ToggleNav` | 宽度 0↔260 补间，180ms OutCubic（原 85ms 只出 3~4 帧，像瞬间贴边） |
| 抽屉打开 | `OpenDrawer` | 抽屉 240ms OutCubic 滑入 + 遮罩 180ms 淡入 |
| 抽屉关闭 | `CloseDrawer` | 抽屉 240ms InCubic 滑出 + 遮罩 180ms 淡出后隐藏 |
| Toast 出现 | `Toast::Show` | 从下方 10px 落位 + 淡入，180ms |
| Toast 消失 | `Toast::PopOut` | 下沉 6px + 淡出，120ms（总显示时长仍按调用方 `ms`） |
| 模态框出现 | `ModalDialog::showEvent` | 遮罩 0→1 + 卡片自下方 10px 落位并淡入，180ms |
| 模态框关闭 | `ModalDialog::Finish` | 反向 120ms 后才 `quit/hide`（结果值仍然同步返回） |
| 明暗主题切换 | 标题栏主题按钮 | 整窗交叉淡出 180ms（盖住全站 QSS 重排） |

### 3.3 全局点击反馈（`Motion::InstallTapFeedback`）

任何 `QAbstractButton` 按下即在**按下点**扩散一圈主色涟漪（320ms，半径 OutCubic，
alpha 按 `1-t²` 收尾）。排除项：`noRipple` 属性（开关自己有一套滑块动画）、
禁用的按钮。开关/滑块/下拉框按下后可能被判成"纵向滑动页面"，出涟漪会误导。

实现要点：涟漪层是**不透明**的——先抓按钮当时的像素当底，再叠径向渐变。
不用 `WA_TranslucentBackground`：`QScrollArea` 内的半透明子控件会被容器重绘盖掉
（实测只剩 1px 亮边）。抓像素放在 `singleShot(0)`，让按钮先画出 `:pressed` 态。

### 3.4 首页（`ui_pages_browse.cpp`）

| 操作 | 动效 |
|---|---|
| 切换分区（点分区栏 / 滑到底点标签） | 下划线在旧/新分区之间滑动 180ms + 卡片墙交叉淡出 120ms |
| 首屏加载中 | 页面顶部 3px 主色扫光（`LoadingBar`，1.1s 循环，数据到位淡出） |
| 加载失败 | 扫光停止；错误态由页面切换或交叉淡出呈现 |
| 卡片按下（QML） | 卡片缩到 0.975 + 45% 底色（90ms）；拖动列表时 `onCanceled` 复位 |
| 卡片长按菜单 | 原生 `QMenu`（保留系统菜单语义，不加自绘动效） |

### 3.5 搜索 / 详情 / 收藏 / 列表

| 操作 | 动效 |
|---|---|
| 发起搜索 | 扫描线开始 + 结果区交叉淡出（"上一次结果/空态"→"正在搜索"） |
| 结果到达（首屏）/ 失败 | 结果区交叉淡出 180ms；**翻页追加不做**（用户正盯着列表底部，整块闪一下更糟） |
| 最近搜索重建 / 清空 | chips 组交叉淡出 120ms |
| 详情封面异步到达 | 封面淡入 180ms（只在该图真的换了时触发） |
| 详情章节表到达 | 章节区交叉淡出 180ms（"加载中"→真实目录） |
| 收藏状态切换（未登录/加载/空/失败/就绪） | 内容区交叉淡出 180ms + 加载态扫描线 |
| 本地目录重新扫描 | 列表区交叉淡出 180ms |
| 清空历史 | 列表交叉淡出到空态 180ms |

### 3.6 阅读器（`ui_pages_misc.cpp` + `reader.cpp`）

| 操作 | 动效 |
|---|---|
| 工具条显隐（点按上方左右角 / F12 / 菜单） | 上条自顶部滑入/滑出、下条自底部滑入/滑出，180ms；滑出屏幕后才 `hide()` |
| 翻页（单页/双页/等宽等非滚动模式） | 旧页面 120ms 淡出（`ReaderView` 视口快照） |
| 翻页（滚动模式） | 既有的 220ms 滚动条补间（不叠加淡出） |
| 切换阅读模式（9 种） | 整屏重排前抓快照，重排后 120ms 淡出 |
| 单张超分开/关、超分完成 | 视口快照淡出 120ms |
| 首次帮助层 | 淡入 180ms；点击后淡出 180ms 再隐藏 |
| 页码滑块拖动 | 跟手（连续输入不做补间） |

**工具条改为浮层**（不在 `QVBoxLayout` 里）：内容区始终占满整页，显隐只改 `pos`，
不触发 relayout，所以既不会让当前页重新布局，也不会在滑出过程中把图片挤变形。
`chromeShown_` 变成状态位（原逻辑依赖 `bar_->isVisible()`，浮层化后不再可靠）。

### 3.7 刻意不做动画的地方

| 场合 | 原因 |
|---|---|
| `QMenu` 弹出/关闭 | 系统菜单的弹出节奏由平台决定，自绘淡入在 Windows/Android 上观感不一致 |
| 设置页 横排↔堆叠 切换（`SetCompact`） | 布局形态变化必须立即成立，插值会把控件挤到重叠 |
| 阅读器缩放（捏合/菜单百分比） | 捏合已是连续手势；菜单百分比直接设置（每帧重采样会掉帧） |
| 下载/批量超分进度条 | 后端尚未接入，没有真实进度可动 |
| 主题切换时的 QSS 重排本身 | 由整窗交叉淡出覆盖，不额外做逐控件过渡 |

## 4. 性能与稳定性约束

1. **不动布局几何**：唯一例外是侧栏宽度（不重排就无法让内容区扩张），因此把它压到
   180ms 并且只动一个 260px 宽的容器。
2. **动画结束即摘效果**：`FadeIn/FadeOut` 在 `finished` 后 `setGraphicsEffect(nullptr)`，
   避免整棵子树永久走离屏合成。
3. **同名 tag 打断**：`Motion::Animate(owner, tag, …)` 只保留最后一个，连点导航/连切
   分区不会叠动画；`Motion::Stop(owner, tag)` 用于"反向操作打断正向动画"。
4. **交叉淡出用图形效果，不用半透明子控件**：`QScrollArea` 里的半透明子控件会被
   容器重绘盖掉（实测只剩 1px 亮边）；`QGraphicsOpacityEffect` 走"离屏渲染 + 按
   alpha 合成"，与容器无关。
5. **旧画面守卫**：`CrossFade` 抓到的图如果"整片同色"（QQuickWidget 的 FBO 在个别
   后端上可能抓成空白），直接换内容，不留"底色渐变"这种假动效。
6. **翻页淡出限流**：只在非滚动模式、且上一帧淡出已结束（`fadeAlpha_ ≤ 0.01`）时才抓
   快照；连续快速翻页时退化为直接换页，避免每翻一页都做一次全屏抓图。
7. **换页期间不抢主线程**：沿用原有策略——覆盖层出首帧后才藏旧页，落地后 48ms 撤层；
   若 48ms 内又发起下一轮（连点导航），这次撤层作废，避免把新覆盖层一起收掉。

## 5. 关闭动效（`--no-anim`）

`MainWindow::SetAnimationEnabled(false)` 同时关闭换页覆盖层与全部控件级动效
（`Motion::SetEnabled(false)`）。退化路径与动画路径**逻辑完全等价**：

* `Animate/Fade/Slide` 直接跳到终值；`CrossFade` 直接 `mutate()`；`Ripple` 不创建层
* 加载条变成静止整宽亮线（状态仍然可见，只是不扫动）
* 分区栏"滚入可视区"直接对齐
* `ModalDialog` 立即 `quit/hide`（返回值不变）
* 工具条直接落位并 `hide()`，不做滑出

## 6. 回归入口

| 参数 | 用途 |
|---|---|
| `--no-anim` | 关闭全部动效，跑与其他用例相同的断言 |
| `--anim-from/--anim-progress/--anim-ms` | 换页动画冻结在指定进度截图（原有） |
| `--anim-back` | 返回方向（Pop） |
| `--anim-fade` | 同级语义（Lateral 交叉淡入，新增） |
| `--drawer-selftest` | 抽屉开/关/遮罩三态（幂等，不受动画时长影响） |
| `--reader-dir X --reader-parity` | 9 模式与手势自检（16 项） |
| `--blank-report` | 设置页开关行排布（动画不得改变几何） |

## 7. 已知取舍

* 涟漪期间按钮显示的是"按下那一刻"的像素（≤320ms），期间 hover/禁用态变化不会立即
  反映在按钮上；换来的是在任意容器里都能稳定合成。
* 主题切换的整窗淡出会抓一次全窗像素（约 10–20ms），换来的是盖住全站 QSS 重排的
  "半新半旧"闪烁。
* 阅读器工具条浮层化后，内容区会延伸到工具条下方（沉浸式）；工具条本身不透明，
  不遮挡阅读。
* 翻页淡出是"整屏替换"的过渡，不是翻书卷曲效果：卷曲需要逐页变形，Widgets 下没有
  可行的低代价实现，也不符合本项目"只动便宜属性"的约束。
